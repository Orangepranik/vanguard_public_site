# Сторінка «Головна» — специфікація desktop-макета

**Статус:** фіксація параметрів від власника (чат, 2026-08-16). План власника: за цими
параметрами він збирає **Figma-макет** сторінки і надішле його (`assets/design/*.fig`);
фронтенд пишеться **за макетом** — саме макет стане джерелом правди для верстки
(див. CLAUDE.md). До макета власник може надіслати фото згенерованої сторінки — за ним
уточнюються відкриті питання (розділ 16).

**Джерело:** згенероване AI-зображення сторінки + параметри власника. Важливо: зображення
має «AI-погрішності» (наприклад, чотири картки категорій різняться по ширині на 5–15 px).
Рішення власника: у Figma сітку робимо **математично рівною**, зберігаючи візуально той
самий результат.

> Зв'язок з документацією: структура головної — `03-pages.md`, текстові wireframes —
> `07-wireframes.md`, дизайн-еталон до-макетного етапу — `09-design-system.md`. Ця
> специфікація і майбутній .fig-макет замінюють їхню візуальну частину (пріоритет за
> макетом).

## 0. Головне правило: що звідки береться

Сторінка CATALOG уже зверстана. З неї на головну **переносяться без змін** спільні
секції; з генерованого зображення береться лише нове наповнення. Маршрут — **`/`**
(зараз там тимчасовий redirect на /catalog — прибрати при верстці).

| Секція | Джерело |
|---|---|
| Header (нав, пошук, «Зв'язатися») | реалізований каталог — `site/src/components/SiteHeader.tsx` (активний пункт — «Головна», див. відкрите питання 1) |
| Breadcrumbs | реалізований каталог — зразок у `site/src/app/catalog/page.tsx`; на головній крихти зазвичай не показують — звірити з макетом |
| Advantages | реалізований каталог — `site/src/components/AdvantagesStrip.tsx` (тексти збігаються) |
| Footer / Main + Footer / Bottom | реалізований каталог — `site/src/components/SiteFooter.tsx` |
| Hero, Category Cards, Flagship, About, Consultation | **нове** — ця специфікація + фото |

Параметри Header/Footer із генерованого зображення (розділи 5 і 12) — **лише довідка**:
у коді канонічними лишаються вже зверстані компоненти каталогу. Для Figma рекомендація —
скопіювати спільні секції з `public_site_catalog_page.fig`, а не перезбирати за зображенням
(пропозиція).

## 15. Розбіжності генерації з реалізованим сайтом (звірити після фото)

- Шапка й футер — див. розділи 5 і 12: канон — компоненти каталогу.
- Токени: базовий фон зображення `#050B11` vs токен сайту `--color-bg #060A0F`;
  акценти `#E64A00`/`#F45100` vs `#E94A02`/`#D04401` — дрейф генерації. Для спільних
  секцій — токени сайту; для нових секцій кольори уточнити за фото.
- Breadcrumbs: на згенерованому зображенні відсутні; власник називав їх серед спільних
  секцій з каталогу, але на головних сторінках крихти зазвичай не потрібні — звірити з
  макетом.

## 16. Відкриті питання

1. Навігація шапки: на зображенні є активний пункт «Головна», у реалізованій шапці його
   немає взагалі (лого веде на /catalog). Додати пункт і вести лого на `/`? — рішення
   власника.
2. Figma-макет сторінки — очікуємо від власника (фронтенд пишеться за ним).
3. Breadcrumbs на головній — звірити з макетом (див. розділ 15).
4. Зображення продуктів (KOZHAN, DELFIN, антени, комплект) PNG з прозорістю — потрібні
   для Hero і карток; у .fig зображення можуть бути вбудовані.
5. Бейджі та статуси флагманських карток 02–03 — звірити з фото.
6. Текст «Найміцність…» у Professional Card — підтвердити чи замінити на «Надійність…».
