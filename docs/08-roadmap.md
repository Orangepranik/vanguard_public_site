# Roadmap, метрики, ризики, відкриті питання

## 36. MVP

### Входить

1. **Головна** — за структурою [03-pages.md](03-pages.md) §13.
2. **Каталог** `/catalog` + 4–6 категорій з картками за §15.
3. **Фільтри** — клієнтські; повні конфіги для 2–3 пріоритетних категорій (детектори, антени), для решти — базові (ціна, наявність).
4. **Пошук** — статичний індекс + словник синонімів + zero-result екран + логування запитів.
5. **Сторінка продукту** — повна структура §16.
6. **Конфігуратор** — підтверджений у MVP: матриця допустимих комбінацій існує (Q4, власник). *Запасний план* для окремих продуктів із неповними даними: їхні варіанти публікуються як окремі позиції з людськими назвами конфігурацій.
7. **Порівняння** — 2–4 продукти однієї категорії (для великого каталогу це must-have, не V2).
8. **«Рішення»** — 6 курированих сторінок, без майстра.
9. **Заявка** — одиночна + список заявки. На старті: збереження заявок у черзі на боці сайту + сповіщення менеджерам (email + Telegram) — рішення Q5; контракт `POST /api/requests` фіксується одразу, самописна ERP підключиться пізніше без змін фронтенду.
10. **/docs, /about, /contacts + сторінка «Партнерам»** (умови співпраці, форма звернення).
11. **Відгуки на сторінках продуктів** — курироване наповнення менеджерами через контент-шар; двоетапна модерація з OPSEC-чеклістом ([04-logic.md](04-logic.md) §22). Форма самостійного подання відгуків — V2.
12. **Блок сумісності «Працює з…»** — типізовані зв'язки між продуктами; мінімум — ручні зв'язки для стартового асортименту ([04-logic.md](04-logic.md) §23).
13. **Наскрізне:** SEO-база (§27), аналітика з подіями (§38), усі стани (§24), accessibility AA (§25), перформанс-бюджети в CI (§26), data exposure review (§30).

### Не входить у MVP

Майстер підбору · кошик і онлайн-оплата · EN-версія · offline PWA · особисті кабінети · розділ історій `/cases` · форма самостійного подання відгуків · повноцінний дилерський портал.

### Умови старту розробки (вхідні дані)

Відповідь на блокер Q1 (бренд) · перелік продуктів від власника для програмного наповнення (назви, характеристики, варіанти, ціни — Q2 вирішено процесно, дані все одно потрібні) · фото за єдиним шаблоном для стартового набору продуктів · тексти призначення для кожного продукту · стартовий пакет відгуків (зібраних менеджерами, із зафіксованими згодами авторів) — хоча б для ключових продуктів.

## 37. V2

- **Майстер підбору** (3–4 кроки над тегами useCases; аналітика completion rate).
- **Онлайн-оплата (автооплата)** — за рішенням власника додається пізніше, коли будуть готові процеси; на старті оплату супроводжує менеджер після заявки. Кошик з оплатою — лише для категорії аксесуарів.
- **EN-версія** (міжнародні фонди й партнери) + hreflang.
- **Service Worker:** офлайн-кеш каталогу й відвіданих сторінок; офлайн-черга заявок.
- `GET /api/availability` — жвавіші статуси наявності без перезбірки.
- **Розділ `/cases` «Досвід застосування»** — курировані історії (задача → умови → результат) і відео роботи; кожен матеріал — через OPSEC-ревью.
- **Форма «Поділитися досвідом»** на сторінках продуктів → черга модерації відгуків.
- **Повноцінний дилерський/партнерський портал** (у MVP — статична сторінка «Партнерам»).
- **База знань / FAQ** (частково — з реальних питань у заявках).

## 38. Метрики

**Інструмент:** self-hosted аналітика (Plausible або Matomo) — трафік військової аудиторії не передається стороннім сервісам; IP не зберігаються; жодних сторонніх трекерів.

### Події

| Подія | Параметри | Що відповідає |
|---|---|---|
| `search_performed` | query, resultsCount | чи користуються пошуком |
| `search_zero_results` | query | де каталог «не розуміє» користувача |
| `filter_applied` | category, filterId, value | які фільтри працюють |
| `card_click` | slug, position, source | CTR карток |
| `compare_add` / `compare_view` | slugs | чи потрібне порівняння |
| `solution_view` | slug | чи працює вісь «задача» |
| `wizard_step` / `wizard_complete` | step | завершуваність майстра (V2) |
| `config_changed` | group, option | що конфігурують |
| `request_open` / `request_submit` / `request_success` | items, sourcePage | воронка заявки |
| `doc_download` | slug, docType | цінність документації |
| `review_media_play` | slug | чи працюють відгуки з фото/відео |
| `review_submit` | slug | потік відгуків через форму (V2) |
| `case_view` | slug | цінність історій застосування (V2) |
| `partner_form_submit` | — | звернення дилерів і партнерів |
| `phone_click` / `messenger_click` | channel | обхідні канали контакту |

### Воронки

- Каталог → картка → продукт → заявка (основна).
- Рішення → продукт → заявка (ефективність осі «задача»).
- Пошук → продукт → заявка.
- Продукт → зміна конфігурації → заявка.

### Здоров'я продукту

Zero-result rate (< 5%) · LCP p75 mobile · частка mobile-трафіку та mobile-конверсія · глибина використання фільтрів · конверсія продукт → заявка.

**Ритуал:** щомісячний розбір zero-result запитів і шляхів без заявки → поповнення синонімів, контенту, фільтрів.

## 39. Ризики

| # | Ризик | Вплив | Мітигація |
|---|---|---|---|
| 1 | Витік чутливих ERP-даних через експорт (собівартість, залишки, постачальники) | критичний | whitelist-DTO deny-by-default, CI-перевірка полів, ручне ревью експорту ([06-tech.md](06-tech.md) §30) |
| 2 | **OPSEC заявок:** база заявок = перелік покупців військового обладнання | критичний | мінімум ПІІ, «підрозділ» — необов'язкове поле, TLS, доступ за ролями, retention-політика, self-hosted аналітика |
| 3 | DDoS / дефейс сайту оборонної тематики | високий | static + CDN/WAF, єдиний POST-ендпоінт з rate limit, моніторинг, бекапи |
| 4 | Публікація ТТХ, корисних противнику (особливо РЕБ) | високий | безпекове контент-ревью кожного продукту; окреме рішення, які параметри РЕБ публічні (Q12) |
| 5 | Немає якісних фото/текстів на запуск | високий (конверсія) | контент-план до старту розробки; єдиний шаблон зйомки; блокер Q13 |
| 6 | Матриця конфігурацій неповна для частини продуктів | низький (наявність підтверджено — Q4) | запасний план MVP §36 п.6: варіанти як окремі позиції з людськими назвами |
| 7 | Зв'язка з самописною ERP відкладається | прийнято як план (Q5) | старт свідомо без ERP: черга заявок + email/Telegram; зафіксований контракт API робить підключення drop-in |
| 8 | Рішення не публікувати ціни | середній (конверсія падає, більше дзвінків) | компроміс «від …» або публічність по категоріях; A/B після запуску |
| 9 | Розповзання скоупу в повноцінний e-commerce | середній | межі MVP зафіксовані; кошик — тільки V2 і тільки аксесуари |
| 10 | Жаргонні запити повз пошук | низький | словник синонімів + щомісячний розбір логів zero-result |
| 11 | **UGC-OPSEC:** відгуки/фото/відео користувачів розкривають позиції, особи, підрозділи | критичний | двоетапна модерація без винятків, чекліст анонімізації ([04-logic.md](04-logic.md) §22), strip EXIF, блюр, згода автора, дати з точністю до місяця |
| 12 | Недостовірні відгуки підривають довіру | середній | у MVP — лише курирований збір від реальних користувачів (verified); без анонімного самопостингу |
